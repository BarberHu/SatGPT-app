# Shared map workspace

Experimental personal GEE uses this same map and layer protocol. See [setup and verification boundaries](../../../PERSONAL_GEE.md). Identity changes clear Agent groups and remount its conversation without recreating the map; AOI and Basic storage formats are preserved.

`ModeRoot` keeps `AppProvider` and `SharedMapProvider` mounted for the workspace lifetime. The Basic panel stays mounted; the Agent panel mounts on its first visit and then retains its chat, input, history and SSE state. Only the business panels and layer groups are switched.

`SharedMapSurface` owns the stable canvas container. `SharedMapViewport` describes its visible rectangle without moving or remounting the canvas. A single layout observer follows sidebars, resizable panels and narrow-screen tabs. `MapScale`, navigation, snapshots, English basemap labels, load/error state and persisted camera belong to the shared workspace.

`MapService` is the engine-neutral application port. Agent result groups are keyed by conversation (`agent:<conversation-id>`), with namespaced engine IDs. Layer visibility is a user preference; group visibility is applied separately. History changes can restore a result extent only through a captured view intent. Mode changes and arriving results never request camera movement. View intents expire after a mode change, a different conversation, or user camera movement.

`MapboxAdapter` is the only engine creator/disposer. `BasicMapPort` is a deliberately Mapbox-specific extension boundary for the existing draw, grid and terrain algorithms in `basic/BasicMapController`. It gives those algorithms scoped IDs (`satgpt-basic:*`, `satgpt-basic-aux:*`), logical visibility, guarded map/DOM listeners and suspended controls. The compatibility `AppContext.mapInstance` contains this scoped port, not the native map. New business components should use the application port instead of extending native-map dependencies.

The saved shared camera (`satgpt:map-view:v1`) includes center, zoom, bearing and pitch. The previous Agent camera key is read as a compatibility fallback without clearing storage. Agent layer preferences retain their existing per-conversation keys and logical result IDs. SSE remains subscribed once after the Agent panel's first mount, including while Static layers is active, and is cleaned up when the workspace unmounts.

Agent analysis areas reuse MapboxDraw, the AOI helpers and the scoped extension port. `MapboxAdapter` owns an additional port on the same engine with `satgpt-agent-aoi` IDs; both ports namespace `draw.*` events as well as sources/layers. The adapter suspends the previous mode before activating the next. `useAgentRegion` owns only its Draw control, never the map. Confirmed geometry uses a read-only Draw mode, so map gestures cannot move vertices. Switching modes cancels an unfinished edit; confirmed selections remain intact. A session change discards its unfinished draft and restores that session's confirmed selection.

`RegionSelection` keeps reversible drafts and detached send snapshots. Confirmed areas (including an explicit null after Clear) use `satgpt:agent:analysis-region:v2:<conversation-id>` with full geometry, name, optional library provenance and outline visibility. Absent v2 keys read the old v1 geometry, then the latest scoped user message. An explicit cleared value takes precedence over history. Existing history/storage is not cleared. New messages and tasks carry `analysis_region` as a GeoJSON Polygon/MultiPolygon geometry and retain bounds. Optional `analysis_aoi` contains only a display name and saved ID/revision; execution and replay never resolve that ID from a library. The backend validates closure, coordinates, topology and limits (2048 vertices, 32 polygons, 64 rings per polygon, 1 m²–5 million km²; no antimeridian-spanning scope). Bounds derived from geometry are for compatibility and framing only.

For each DSH run the agent atomically writes its task/conversation identity, bounds and exact geometry to a runtime-private context file. The GEE plugin captures it per tool call before entering the existing worker queue. Every Python execution creates fresh `analysis_region_geojson` and `analysis_region` (`ee.Geometry`) variables; viewport requests receive a rectangle snapshot. Agent instructions require the geometry for spatial filtering, clipping and statistics. Model-based place conflict clarification uses ordinary conversation context: it does not guarantee all conflicts will be detected, and arbitrary generated Python is not proven to obey the AOI.

Offline verification: `harness/.venv/Scripts/python -m unittest discover -s harness/tests -p 'test_*.py'` and `node --test harness/tests/*.test.mjs`. For an isolated real page/GEE check, start `python -m harness.tests.region_page_server` on an unused `AGENT_PORT`, serve the built frontend with that backend, then run `python -m harness.tests.live_analysis_region` with the same port. Both use the root configuration; the server keeps test history under `harness/state/region-verification/`, leaving existing sessions untouched. Live verification consumes the configured model/GEE services and emits a safe report under `outputs/`.

Agent result layers retain their own `generation` recipe: original Python code, visualization, metadata, legend, bounds and the task's exact analysis context. The layer details expose this code through the existing code viewer. `POST /api/harness/conversations/{conversation_id}/layers/{layer_id}/reload` resolves only that saved recipe; it does not accept replacement code or use the current map/selection. Reload runs the existing GEE Python worker in an isolated, bounded subprocess without creating a chat task or calling the model. Successful results update the original history layer with a new service URL, preview, `reload_version` and `reloaded_at`; failures leave the previous result intact. Duplicate reloads of one layer are rejected and at most two worker reloads run concurrently.

`MapService.replaceLayer` refreshes the existing scoped source while preserving visibility, opacity, order and camera. Captured conversation scopes prevent an in-flight reload from appearing in another chat or resurrecting a removed layer. Tile errors show “Layer unavailable or expired”; this is an availability indication, not a guaranteed expiry detector. Reload is also available before a tile error. Legacy records recover recipes only from layer-owned code or one unambiguous successful `gee_layer` trace with its original user scope; missing/ambiguous recipes remain readable with reload disabled. Run `python -m harness.tests.live_layer_reload` against an isolated server containing a generated layer to verify real GEE replay and PNG retrieval without printing service URLs.

## Basic responsibilities and regression checks

`ModeRoot` is the only workspace mode switch. `AppContext` keeps Basic questions, map controls and AOI drafts; it no longer hosts the retired Flood Agent workflow. Existing business-layer IndexedDB namespaces remain readable. Basic selection writes the versioned `satgpt:basic-study-area:v2` snapshot and reads v1 as a fallback without deleting it.

`BasicMapController` owns grid selection, drawing/editing, selected-area presentation, terrain and buildings. Selecting an area does not request an analysis. `PresetLayerStore` owns independent preset selections and requests, and `PresetMapController` alone projects their results into `basic:presets`. Basic questions return an answer and retain the existing optional country focus; they do not load the retired Ask raster stack. Backend compatibility endpoints and raster algorithms remain available.

From `frontend/`, run `npm test` for Vitest regressions, `npm run test:node` for chat/grid integration checks and `npm run build` for production validation. The grid integration test checks complete geometry at five zoom levels and nine click positions, then submits that geometry through the current preset request adapter. Shared-map and preset tests cover hidden-mode responses, layer choices, drawing, cancellation and disposal.

## Saved analysis areas

Basic and Agent share `AoiLibraryProvider` and the `aoi/` repository. Saved areas are local to this browser profile and site origin, not a signed-in account or cloud backup. Different ports, browsers and devices have separate libraries. Export GeoJSON to retain a portable backup; clearing site data removes the local library.

Select, draw, upload or capture an extent, then choose **Save area**, name it and save locally. **Saved areas → Use** applies a detached copy to the current Basic panel or Agent conversation. Saving does not run analysis or silently change the current selection. Library names and geometry can subsequently change without changing an adopted selection, historical message, preset row or layer replay recipe. **Save this area** on a historical message creates a separate record. **Locate** moves only the camera. **Hide boundary** changes presentation; **Remove selection / Clear analysis area** changes only the current scope, and Agent then uses the viewport for new requests. Clearing does not delete library records and survives refresh.

**Edit on map** reuses the existing mode's Draw control and edits a draft. Confirming adopts the edited geometry, while saving changes explicitly updates the referenced library revision. Cancel or mode/conversation changes discard the draft. **Save as new** retains the old record. Agent validates its stricter topology/size limits before adopting an area; unsupported geometry stays in the library without truncation. **Delete** is reversible through **Show deleted → Restore**. GeoJSON import accepts Polygon/MultiPolygon Features or compatible collections up to 2 MB and opens a naming dialog; export retains the complete polygon rings and components.

The repository reuses the existing `satgpt-business-layers` database and `layers` object store with the fixed namespace `aoi-library:local:v1`. Each record has a stable ID, full GeoJSON Feature, derived bounds, source, name, timestamps, revision and `deleted_at`. Per-record read/write transactions reject stale revisions instead of replacing the whole library. A storage notification refreshes other pages' lists without overwriting their active selections. A failed read blocks writes; failed commits report an error while keeping the prior record. **Retry / refresh** reloads and retries migration.

On first load, migration reads all legacy IndexedDB namespaces and the old Basic and per-conversation Agent v1 selection keys. Every valid source is copied with its own atomic migration marker. The original records and keys remain untouched; retries cannot resurrect an edited or deleted import. Invalid sources are reported and retained for recovery. The library does not reconstruct the original shape of data that had already been deleted before this change. Legacy duplicates may appear as separate recovered records to avoid discarding distinct source entries.

`aoi/repository.test.js` uses fake-indexeddb to exercise actual IndexedDB transactions, reopen, migration, stale writes and aborts. `aoi/AreaControls.test.jsx` covers cross-mode adoption, rename/delete/restore, errors, delayed saves, import/export and chat-form isolation. These are automated simulated checks, separate from browser and real GEE validation.

## Desktop overlay layout

`LayerPanel` is the common presentation shell for Basic and Agent Current layers. Each mode still owns its records and callbacks. The panel stays at the map's upper right (16 px from the top, 56 px from the right to clear map tools), up to 360 px wide and 46% of the map-slot height (capped at 380 px). Its width also respects the map's available space. Its list scrolls independently. Collapsing the panel retains the mounted cards and their details; AOI editing temporarily hides the panel without changing the user's expansion preference or layer visibility. Basic questions has lower layout priority: it is centered below the actual Basic map slot, adjusts when the library collapses, and scrolls within a height bound that leaves the upper layer panel clear. Opening questions never suppresses Current layers.

At desktop widths above 960 px, Basic's viewport excludes the visible library width and expands again when the library collapses. CSS defines the slot; the existing shared observer resizes the single map without a fit/focus request. The shared ruler is at the actual map's lower right without a white background, rounded plate or shadow; it measures at its current position and is absent when the map slot is hidden. It does not have a second mode-specific instance.

Basic's selected-area summary keeps save/reuse actions visible. Selection and drawing methods expand on demand and remain expanded while no selection exists or an edit is active. Boundary visibility and removal are in More area actions. Saved-area dialogs keep their header and tools outside the scrolling list. Agent keeps its existing Composer entry and displays the selected name in the map context. Current-layer cards use compact legends; opacity and full metadata stay in Basic details. Normal Agent replay is in details, while tile failure, replay failure and running replay expose an inline action/status. All replay requests still use the original layer recipe.

The desktop pass does not redesign mobile navigation or introduce account synchronization, storage migrations, algorithms or backend API changes. Use browser geometry/hit-testing in addition to unit tests when checking overlay overlap and click interception; DOM-only test environments do not provide real layout measurements.
