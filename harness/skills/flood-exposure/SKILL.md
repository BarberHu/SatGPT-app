# Potential flood exposure

Plan only the requested assets and outputs. Numeric questions need statistics; include an interactive result layer only when requested or explicitly approved. Honor statistics-only requests. For new calculations, include the outputs in the plan and wait for approval; interpreting or summarizing completed results needs no new calculation or approval cycle. When reusing a saved flood result, keep its confirmed original study area and clarify any conflict with the current task scope before analysis.

1. Start with a verified event flood mask that Earth Engine can read or reproduce. If the user specifies a product or event ID, validate that input first. Confirm the dates, geometry, flood class, permanent-water treatment, and valid observation coverage inside the exact AOI. A public event product can be used directly, and a mask already derived in the current task can be reproduced with the verified recipe. A screenshot or display tile provides visual context only. Derive a new mask using `flood-extent` only when the approved plan authorizes it. When asked to reuse a saved mask, do not derive it again.

For GFD (`GLOBAL_FLOOD_DB/MODIS_EVENTS/V1`), filter by the numeric `id` and exact AOI. Check the match count before taking the first image. Then obtain actual dates, bands, and valid support of `flooded` with `clear_views` inside the AOI. The asset supplies `jrc_perm_water` for permanent water. Group small metadata and AOI checks in one result per stage.

An overlapping footprint and a nonempty event match do not establish pixel coverage. Establish the flood mask's valid support in the AOI before querying population. For any approved flood mask, a successful zero valid-count or zero valid-area result is conclusive for that mask, grid and AOI. End the analysis and report the gap immediately, with no follow-up tool calls for that event. An error or an unverified null count allows one targeted check of the same mask, grid and AOI before reporting that coverage could not be established. A valid zero flood class area is a zero detection on the product's support. Preserve the source's event interval and limitations through the exposure result. With low-confidence urban detection, describe the estimate as potential exposure within the detected footprint and identify which assets lack valid hazard support.

For an approved GFD event and a single legacy WorldPop count image (`WorldPop/GP/100m/pop`, 2000–2020) in a confirmed latitude-longitude rectangle, use `flood_population_exposure` when native cell overlap fits the approved method. Pass the numeric event ID, country code, year, and an explicit permanent-water decision. This tool checks flood support before reading population, checks both native grids, and returns UTC event dates and aggregated statistics. Use its `status` to distinguish an event match gap, no eligible flood observations, no jointly valid data, and an estimate that may be zero. If the tool reports unsupported geometry or grids, use the existing `gee_eval` route only when the approved plan already covers the alternative. A coverage gap is a stop condition.

Set `show_on_map: true` when the approved plan includes a population layer. The layer shows native WorldPop density in people per square kilometre within the jointly valid flooded area. The exact area-weighted people estimate comes from the native overlap calculation. Use `map_status` to distinguish a published layer, unavailable coverage, a valid empty flood overlap, and a publication failure. Keep a verified estimate when publication fails.

For OSM facilities or building footprints, use the same mask checks above. Use a band with 1 for observed flood, 0 for observed dry, and masked pixels for unobserved areas. Query `osm_pois` or `osm_buildings` for the exact task AOI and run `gee_osm_analyze` with its artifact reference. Use `point_sample` with `hit_value=1` for facilities and `building_flood` for footprints. Report hits, partial or missing raster coverage and both source dates. Building areas describe the portion of each footprint inside the AOI. The remaining steps apply to population and land-cover rasters.

For road exposure against a prior result, use `geo_data_search` to find the matching flood and road vectors. Use the same confirmed original area, even after the map moves. If needed, ask the user to choose a flood or publish a suitable result in an earlier turn. If roads are missing, query `osm_roads` with `flood_data_ref`, then pass its `data_ref` as `road_data_ref` to `road_flood_exposure` with the same `flood_data_ref`. When a map is requested, set `show_on_map` on the exposure tool. Report centerline length and the breakdown by road class, including observed, inundated, unobserved and excluded lengths, road classes and snapshot date. For exposure percentages use observed classified road length as the denominator; for road observation coverage use total mapped centerline length. Spatial overlap is potential exposure.

2. Verify the selected public population or land-cover data, including dataset version, data year, bands, units, grid, and class definitions. Use `gee_catalog` when a dataset ID is uncertain and `gee_eval` to verify inputs and coverage. After verifying the mask, check that the exposure data year is appropriate for the event and disclose any mismatch. Report the intersection of valid coverage for the mask and exposure data. Keep missing pixels distinct from valid zeros and valid dry pixels.
3. Calculate flooded fractions from the jointly valid observed area. For people per cell, use the full native population cell area as the denominator and state the within-cell uniform-density assumption. For density, multiply by confirmed flooded area in matching units. Preserve valid zero values and keep masked data outside both the estimate and joint coverage. When using a finer categorical sampling grid to approximate overlap, record the CRS, affine origin and spacing. Sample classes and native population density by nearest neighbour. Avoid interpolating per-cell counts or assigning a whole population cell to the class at its centre. Plan one bounded comparison with native overlap or a second sampling grid where feasible. Compare to the approved tolerance; label precision unverified if the tolerance is exceeded or the comparison cannot be completed. A smaller integration grid keeps the source flood resolution. For categorical land cover, sum confirmed flooded area by class and report mixed-cell treatment.
4. For the general-purpose path use `gee_eval` with exact `analysis_region`, the approved grid, and `ee.Image.pixelArea()` when calculating area. Measure joint valid flooded area separately for each asset to determine whether there is an exposure footprint to map. Reuse the verified expressions in separate `gee_layer` calls for population and land cover when included in the plan. Use the same flood mask, observations, permanent-water treatment, source version, grids and joint validity as the estimates. Display population density with its unit. For land cover, remap selected class codes to consecutive integers for display and use matching categorical legend labels. Leave pixels outside joint valid flood support transparent. Explain a coverage gap, empty overlap, or map failure for the affected asset and keep the corresponding verified statistics. Report population and units, actual event dates, population year, grid, treatment of permanent water, AOI and joint valid areas, and the denominator for every coverage fraction. Where available, give the fraction of the mapped flood area that also has valid population data. Spatial overlap measures potential exposure.

Nearest-neighbour is Earth Engine's default. Leave `resample()` unset for categorical grids and native density samples. Reuse successful calculations and keep any approved precision check bounded to the same input data and AOI.

Source: [UN-SPIDER population and land-cover overlay, steps 11–13](https://un-spider.org/advisory-support/recommended-practices/recommended-practice-google-earth-engine-flood-mapping/step-by-step).
