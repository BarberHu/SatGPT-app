# Potential flood exposure

1. Start with a verified event flood mask that Earth Engine can read or reproduce. If the user specifies a product or event ID, validate that input first. Confirm the dates, geometry, flood class, permanent-water treatment, and valid observation coverage inside the exact AOI. A public event product can be used directly, and a mask already derived in the current task can be reproduced with the verified recipe. A screenshot or display tile provides visual context only. Derive a new mask using `flood-extent` only when the approved plan authorizes it. When asked to reuse a saved mask, do not derive it again.

For GFD (`GLOBAL_FLOOD_DB/MODIS_EVENTS/V1`), filter by the numeric `id` and exact AOI. Check the match count before taking the first image. Then obtain actual dates, bands, and valid support of `flooded` with `clear_views` inside the AOI. The asset supplies `jrc_perm_water` for permanent water. Group small metadata and AOI checks in one result per stage.

An overlapping footprint and a nonempty event match do not establish pixel coverage. For any approved flood mask, a successful zero valid-count or zero valid-area result is conclusive for that mask, grid and AOI. End the analysis and report the gap immediately, with no follow-up tool calls for that event. An error or an unverified null count allows one targeted check of the same mask, grid and AOI before reporting that coverage could not be established.

For OSM facilities or building footprints, use the same mask checks above. Use a band with 1 for observed flood, 0 for observed dry, and masked pixels for unobserved areas. Query `osm_pois` or `osm_buildings` for the exact task AOI and run `gee_osm_analyze` with its artifact reference. Use `point_sample` with `hit_value=1` for facilities and `building_flood` for footprints. Report hits, partial or missing raster coverage and both source dates. Building areas describe the portion of each footprint inside the AOI. The remaining steps apply to population and land-cover rasters.

For road exposure against a prior result, use `geo_data_search` to find the matching flood and road vectors. Use the same confirmed original area, even after the map moves. If needed, ask the user to choose a flood or publish a suitable result in an earlier turn. If roads are missing, query `osm_roads` with `flood_data_ref`, then pass its `data_ref` as `road_data_ref` to `road_flood_exposure` with the same `flood_data_ref`. When a map is requested, set `show_on_map` on the exposure tool. Report centerline length and the breakdown by road class, including observed, inundated, unobserved and excluded lengths, road classes and snapshot date. For exposure percentages use observed classified road length as the denominator; for road observation coverage use total mapped centerline length. Spatial overlap is potential exposure.

2. Verify the selected public population or land-cover data, including dataset version, data year, bands, units, grid, and class definitions. Use `gee_catalog` when a dataset ID is uncertain and `gee_eval` to verify inputs and coverage. After verifying the mask, check that the exposure data year is appropriate for the event and disclose any mismatch. Report the intersection of valid coverage for the mask and exposure data. Keep missing pixels distinct from valid zeros and valid dry pixels.
3. Align or aggregate to an explicitly stated working grid. Calculate each exposure cell's flooded area fraction from the valid flood observations using area-weighted overlap. With a coarser flood grid, use native-cell overlap or a documented finer categorical sampling grid to approximate it. Avoid classifying an entire population cell by its centre when computing flooded fractions. Keep track of incomplete observation within cells and use mutually valid support, rather than treating masked subpixels as dry or scaling observed impacts to the whole AOI. For population measured as people per cell, multiply by the share of the cell's area confirmed flooded, using the full cell area as the denominator. State the implied within-cell population distribution assumption. For density, multiply by confirmed flooded area in the matching area unit. Avoid interpolation or reprojection of per-cell counts that changes their total. For categorical cropland or built-up, sum confirmed flooded area within those classes and explain any mixed-class or partial-cell assumptions. Never interpolate categorical codes.
4. Use `gee_eval` for requested sums with exact `analysis_region`, appropriate resolution, and `ee.Image.pixelArea()` when calculating area. Use `gee_layer` if the user requests a map. Use restricted Python with the preloaded `ee` and `analysis_region`, and assign `result` explicitly. Report potential exposure with units, mask and exposure data sources, event date or range, exposure data year, grid and coverage, and the partial-pixel treatment. Report the limits of spatial overlap for inferring observed impacts.

Source: [UN-SPIDER population and land-cover overlay, steps 11–13](https://un-spider.org/advisory-support/recommended-practices/recommended-practice-google-earth-engine-flood-mapping/step-by-step).
