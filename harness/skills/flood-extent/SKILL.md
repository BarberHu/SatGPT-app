# Event flood extent

1. Use the confirmed `analysis_region` and authorized event or comparison windows. Convert dates to the corresponding half-open Earth Engine intervals and explain the dates used. If an essential date or region is ambiguous, ask for it. Keep acquisition queries inside explicitly requested windows and the exact geometry, including optional optical checks and dated water baselines. If the user specifies a sensor, use it for the event comparison. A static water climatology can provide context when appropriate.
2. Choose the approved public event flood product when it has verified dates, classes, flood semantics and valid coverage. If it is unsuitable, use comparable Sentinel-1 observations only when the approved plan includes that fallback. Otherwise, explain the gap and wait for approval of a revised plan. Verify uncertain dataset IDs with `gee_catalog`. Use `gee_eval` for counts and actual acquisition dates after filtering by the authorized windows and region. Match instrument mode, resolution, polarization, orbit direction and relative orbit. Check common valid coverage, since overlapping footprints or nonempty collections alone do not establish usable coverage. Where several orbits are needed, compare each matching orbit separately. An empty or incompatible pair requires a gap report and no flood classification for that pair.
   For `COPERNICUS/S1_GRD`, apply the approved filters using `instrumentMode`, `resolution_meters`, `transmitterReceiverPolarisation` with `ee.Filter.listContains`, `orbitProperties_pass` and `relativeOrbitNumber_start`. Use the same approved filters for metadata checks and retries. Return counts, scene IDs and acquisition times as scalars or flat lists. Query the primary windows first. If a window is empty, report the gap and query a fallback only if the approved plan covers that condition. [Earth Engine Sentinel-1 catalog](https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_S1_GRD)
3. For Sentinel-1 open-water change detection, use a documented backscatter decrease in a consistent measurement domain. `COPERNICUS/S1_GRD` is in dB. A decrease can be expressed as pre-event minus event dB, or as a pre-event to event ratio of positive linear power. Record domain, direction, threshold, and any smoothing or filtering. The UN-SPIDER tutorial's example threshold of 1.25 belongs to its tutorial procedure and has no universal interpretation across domains or sites. If a locally validated threshold is unavailable, state that the chosen threshold is exploratory and subject to false detections. Use a verified stable or same-season water baseline where possible to distinguish newly inundated land from normal water. Describe the choice and effects of any terrain or connectivity filters.
4. Keep valid but undetected pixels separate from no-data and excluded pixels. Check how the water reference encodes land and missing values before masking or combining it. Quantify common valid coverage within the AOI at a stated scale before reporting area or publishing a flood layer. When coverage is partial, report area only for the observed subset. Discuss SAR limitations in built-up areas and dense vegetation and the possibility of missing peak inundation. Use optical support only when relevant to the request and available within its scope. Retain cloud and other blind areas as unknown.
5. For a mapped classification with a confirmed polygon, use `gee_publish_flood` with verified scene IDs, method, and the local UTM grid. Supply one band with 0 dry, 1 detected flood, 2 observed but excluded and masked unknown; restore dry zeros after connected-component filtering while preserving the original observation mask. The tool calculates areas on its grid, reports coverage, publishes the map and saves the result for later road exposure. Use `gee_layer` for diagnostic imagery. For area-only analysis use `ee.Image.pixelArea()` for the verified flood class in `analysis_region`. Report source, actual acquisition dates, AOI, method and limitations.

Reuse the existing read-only Earth Engine tools. Supply restricted Python with the preloaded `ee` and `analysis_region`, and assign `result` explicitly. Keep queries small. Use `gee_preview` only if visual inspection is needed.

Sources: [UN-SPIDER SAR mapping workflow](https://un-spider.org/advisory-support/recommended-practices/recommended-practice-google-earth-engine-flood-mapping/step-by-step), [UN-SPIDER limitations](https://un-spider.org/advisory-support/recommended-practices/recommended-practice-google-earth-engine-flood-mapping/in-detail), [UN-SPIDER multisensor limitations](https://un-spider.org/node/13456), [Earth Engine Sentinel-1](https://developers.google.com/earth-engine/guides/sentinel1).
