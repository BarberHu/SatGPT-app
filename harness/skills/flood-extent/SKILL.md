Preserve permanent water, generic excluded areas, and out-of-coverage pixels outside propagation.

## Sentinel-1 method selection

1. **Plan and diagnose.** Use the approved area, event window, pre-event baseline windows and land-cover sources. A conditional plan can authorize both detectors and define their triggers before queries. Plan to check a multi-scene baseline first for open terrain, with a default of at least two valid pre-event observations per pixel. State its minimum joint coverage over the target area and the separate sample and coverage gates for the historical dual-direction method. Respect explicitly approved scenes, methods and windows. With an appropriate dated and approved land-cover source, measure known and unknown support, built-up areas, open terrain and vegetation or wetlands. ESA WorldCover 2020 `Map` class 50 is one option near its epoch. Consider where built-up cover is concentrated and whether the task targets streets or buildings as well as open land.
2. **Test comparability and support.** Identify observations relevant to the event timing. For each authorized orbit, inventory pre-event and event acquisitions by relative orbit, pass, instrument mode, resolution and polarization. Exclude known flooded or materially unrepresentative dates from the baseline and give the reasons. Consider seasonality, data gaps and matching acquisition conditions. Use the selected pre-event band collection's per-pixel `count()` and measure the area where it meets the approved minimum and the event observation is valid. Apply the historical method's own sample gate over its target land-cover groups. Reuse the same eligible observations for each baseline. Use the exact target area as the coverage denominator, with separate coverage over important land-cover groups when needed. An inventory or footprint check alone cannot pass the pixel gate. Distinguish empty collections, inadequate support, and failed or null queries.
3. **Select and explain the method before mapping.** On open terrain, if the multi-scene gate passes, use the per-pixel median of the eligible pre-event observations for the UN-SPIDER-style backscatter decrease workflow. Mask pixels that fail the sample or event-validity gate as unknown. If the verified multi-scene gate fails for the target, use a single-scene fallback only if the approved plan permits it, the scene represents normal conditions and its common coverage passes. Report the measured reason for using one scene. On built-up or mixed terrain where built-up pixels matter, use the historical dual-direction method when its support gate passes for the target. With insufficient historical support, use the approved open-water workflow only over verified open subareas with adequate support. Keep unsupported built-up and unverified land-cover areas unknown in a restricted screen. If no approved method has adequate observations, report the gap and stop. Changing the approved scope or using an unapproved method needs a revised plan.
4. **Run the selected detector.** For the historical method, compute a per-pixel reference distribution from the eligible pre-event observations on the working grid. An exploratory implementation can combine lower and upper quantiles with minimum departures below and above the historical median, with quantiles, change magnitude and filters justified for the available samples. Compute both directions and report separate areas and coverage by relevant land-cover groups. Treat positive anomalies as candidates. Explain how land cover and plausible inundation context support their inclusion, and disclose other causes of brightening and the remaining blind spots. Apply the approved permanent-water baseline consistently to both directions. Keep held-out products and field reports out of branch selection, threshold tuning and filtering.
5. **Keep the run reproducible.** For a single-date task use the relevant event acquisition. For approved flood evolution analysis, classify each event date separately against the approved baseline, with its own extent, acquisition date and valid coverage. Aggregate the baseline in GEE and return summary evidence. Record the full filters, actual eligible pre-event date range and scene count, baseline method, event acquisition times, sample and coverage gates, rules and grid. `scene_metadata` and `gee_publish_flood.scene_ids` allow up to 16 entries per call. When listing representative historical IDs, identify them as such in provenance and report the full eligible count. Apply the same gated support and permanent-water mask to the combined result and diagnostic outputs.

## Acquisition times and grid

- Distinguish the reported disaster date, baseline and event acquisitions, and the observation interval of a composite event product. For scene inventories use `gee_eval` with `result_format="scene_metadata"`. Return a list of rows containing `scene_id`, its own `system:time_start` as `time_ms`, and optionally `role` (`baseline` or `event`). Copy `time_utc` directly from the result. Retain null as unknown. Use verified metadata for comparisons rather than times encoded in scene names or inferred from product titles.
- Verify the intended UTM hemisphere from AOI latitude and use the approved zone. For cross-equator, cross-zone or polar work, resolve any projection warning in the plan. Use one explicit transform and AOI for comparable reductions. Report the actual publisher's CRS, scale and affine origin for the saved result. State the grid separately for any statistic computed on another grid.

For example, after checking the filtered collection count and confirming that it is at most 16, pair each scene ID with its timestamp in the same record:

```python
result = ee.List(scenes.sort('system:time_start').toList(16)).map(
    lambda item: ee.Dictionary({'scene_id': ee.Image(item).get('system:index'),
                                'time_ms': ee.Image(item).get('system:time_start'),
                                'role': 'event'}))
```

## Built-up and mixed areas

- A fixed VV or VH decrease detects candidate open-water flooding. Buildings, radar geometry and other scattering effects can hide water or change the sign of the backscatter response. High shared observation coverage describes sensor support. It does not establish high detection confidence in built-up pixels. Report class 0 as “no inundation detected by this method” for these pixels. Keep radar blindness or missing observations separate from valid non-detections. Describe double-bounce, layover, subpixel water and flood recession as possible explanations unless the run independently verifies them.
- If the plan authorizes land cover, report observed coverage and candidate flood results separately for built-up and other areas on the same grid. Disclose the limitation with the result and pass it to exposure analysis. An available reference must have a documented source, footprint, actual time, and class semantics. Compare standing water with standing water on shared valid support. Describe changes over time when acquisitions differ. Keep held-out references out of method selection and threshold tuning.

## Sentinel-2 optical change detection

- Use approved L2A acquisitions, tiles and windows. Prepare an explicit valid mask for each period from the approved scene-classification (SCL) labels and valid reflectance bands (B3 and B8 for NDWI). Check each period's coverage, then the intersection on one fixed grid over the exact AOI. Report all three areas and fractions using the same AOI denominator. Use area-weighted support or an unweighted pixel-centre count consistently. Tile cloud percentages describe the tiles, while the gate uses the AOI.
- In `COPERNICUS/S2_SR_HARMONIZED`, the `MGRS_TILE` property omits the leading `T` used by the scene-ID suffix (for example `30SYJ` versus `T30SYJ`). Prefer the approved full scene IDs when provided. If metadata returns zero matches, confirm the exact property encoding within the same approved AOI and dates before concluding that imagery is unavailable.
- Define the minimum co-valid fraction in the proposed plan. If measured coverage is below it, report the acquisition IDs, tool-formatted UTC times and coverage gap, then finish the optical path without classification, area estimation, map or exposure calls. Report null and query failures separately. Apply any optical fallback only if already authorized and after establishing its trigger.
- When the gate passes, apply the approved NDWI change rule within co-valid pixels; preserve other pixels as unknown. For same-period mosaics report all contributing acquisition times. If cross-date compositing or a second sensor is approved, keep each observation date, sensor and support explicit in the result. Pass the approved coverage floor to `gee_publish_flood` when its observed-class definition matches the optical support gate.

Reuse the existing read-only Earth Engine tools. Use top-level assignments with the preloaded `ee` and `analysis_region`, and assign `result` explicitly. Return labeled scalar statistics rather than histogram arrays. Use Earth Engine image methods `.And()`, `.Or()` and `.Not()` for Boolean combinations. Cast a binary mask to an integer before connected-component filtering. Reuse scene IDs, coverage and threshold evidence from successful calls. For a mapped classification, publish the reusable mask directly and use a preview or a separate diagnostic layer only when needed.
